# Journal 每日流程

首页今天的日期按钮和 `/journal-review` 使用同一流程。目标是每天用几分钟理解经历和判断，工作与生活都可以写。没有 weekly 模式，不建立面试故事库，不要求每天得出教训。AAR 是反思框架，尚未出现的结果允许保持未知。

## 文件与边界

- 先读 `system/modules/journal/module.md`。只有 `enabled: true` 才继续。
- 每篇记录独立存为 `Journal/Daily/YYYY-MM-DD-timestamp.md`。日期采用开始本篇时的设备本地日期，timestamp 为 Unix 毫秒时间戳（13 位数字）。新建时如重名，递增毫秒值找到空闲路径，禁止复用或覆盖已有文件。同一天可以有多篇，不按日期合并。
- 模板为 `Templates/Journal Daily.md`，替换 `{{date}}` 和 `{{day}}`。每篇围绕一个话题，相关补充写回本篇，无关话题另建文件。同一对话继续或保存重试沿用目标路径及 session。跨午夜的已有记录保持原日期和路径。旧的 `YYYY-MM-DD.md` 仍可读取、回看和补充，不自动迁移。
- 滚动回顾：`Journal/Review.md`，缺失时从 `Templates/Journal Review.md` 初始化。无需创建周文件。
- 运行时只允许写本次各篇目标 daily、涉及后续结果的原 daily 和 Review.md。不改本指引、模板、Home、其他模块和插件设置。读取资料限于本指引、模块清单、上述模板及 Journal 记录。
- 原始记录是用户表达的事实、判断与感受，不能用 AI 文案冒充。AI 的整理放在 AAR / Review，保持事实与推测的区分。手动记录始终保留。

## 固定七步

### ① 准备

确认本地日期、目标文件、session 标识。首页已提供就沿用；否则按命名规则为新篇创建路径，以文件名（不含 `.md`）作为 session。本次保存和重试始终沿用。读取目标文件和 Review；缺失才按模板初始化。初始化失败就说明失败，不假装开始已准备好的记录。

### ② 回看之前

读取 Review、今天已有的各篇记录、最近 7 个本地日期的所有 daily。通过 vault 文件列表查找所有 daily 中“想再回看的事”章节的未完成 checklist，包括更早尚未关闭的事件。不要把整库记录全部塞进对话；先看未完项与近期摘要，再按相关链接展开旧事件。

简短带回 1-2 件最相关的事情，询问是否有新结果。例如：“上次你打算先做回滚演练，现在有结果了吗？”有结果则收集事实和影响，稍后补回原事件；没有则保留待观察，不强迫闭环。首次使用没有历史就直接进入今天。用户说“先记今天”时跳过回看。

### ③ 记录今天

先让用户自由讲：“今天有什么事情、决定或感受，你想留下来？”不用先发整张问卷。每篇围绕一个话题，相关的几件小事可以放在同篇；出现无关话题时另建文件，并分别维护路径及 session。区分用户自己的角色、行动和团队结果。本篇已有记录则继续补充，不从头重复问；当天其他篇仅作回看背景，不把新篇追加进去。

### ④ AAR 反思

每个值得留下的事件按以下四问整理；对话时一次只问一个最有帮助的问题：

1. 原本希望怎样：情境、角色、目标，必要时补当时掌握的信息。
2. 实际发生什么：用户做了什么、采取何种行动、当前结果；未知结果明确写“待观察”。
3. 为什么：当时如何判断、有哪些选项或依据。区分当时的想法与现在的解释。
4. 下次保留、改变或观察什么：有依据的体会、小尝试或待观察点；没有就如实保留，不强行生成改进。

四项已经足够具体就停止追问。不追求模板字数，也不把一次经历过早归纳成“你总是这样”。用户暂时不知道可以留下问题，不编造结果或所谓 learning。

### ⑤ 收尾

用几句话回放重要理解，简短确认有无自然产生的小尝试或后续要再看的事。没有就留空。信息足够时主动告知可以保存。

用户在任何阶段说“今天到这”“保存一下”“结束吧”等结束信号时立即进入保存，不再为凑齐四问追问，也不重复索取保存授权。明确说“不要保存”则尊重并停止，不能冒充已保存。

### ⑥ 保存数据

写前重新读取每个受影响文件，再做最小的章节/事件更新。不要用启动时的整篇旧副本覆盖现有文件；同一段被另一设备改动时保留双方内容，说明冲突并确认合并。

- **本篇 daily**：将本次用户原话按本地时间追加到“原始记录”，不包含模型提问、系统启动提示。以 `<!-- journal-session: SESSION_ID -->` 标记本次原话区块，结束标记为 `<!-- /journal-session: SESSION_ID -->`。重试先检查标识：已存在则只在同一区块补上尚未保存的原话，不整段重加；原有文本有变化则保留并确认合并。AAR 按 `### 事件标题` 分块，用四个加粗问句整理；未知项如实保留。已有相关事件就补充，不重复写成新事件。
- **待回看事件**：只在 daily 的“想再回看的事”中使用 `- [ ] 事项`，尽量带原事件的 `[[实际存在的路径#事件标题|事件]]` 链接。一事件一项，不默认加截止日期。用户明确表示以后再看结果/检查尝试时可建项；仅由 AI 推测的先询问。跨日提到同一事时找到原项并续接，不在今天另建一个。用户不再关心也可勾选，并记录原因。
- **后续结果**：在原 daily 的“后续补充”追加带日期的结果并引用原事件，保留当时原话与判断；有结果或决定停止跟踪时勾选原 checklist。记录还没出结果时保持未完成。
- **Review.md**：维护近期经历、当前理解、正在尝试与观察、最近一次回看，简短且链接真实来源。整理新理解时保留支持它的证据或说明它只是推测。未完事项以 daily 原项为准，Review 只引用，不复制第二份 checkbox。原 daily 保留完整历史，Review 是可更新的滚动摘要。

不要顺手补造用户没说过的原话、日期、经历或结论。多文件写入不是事务：逐个完成，记录已成功步骤；失败后重试先读现状，避免重复。

### ⑦ 核对与展示

逐个读回本次各篇记录、涉及的原 daily 和 Review，确认原文保留、AAR 及跟进状态正确、没有重复项。全部成功后才将 Review 的 `last_reflected` 更新为带时区的本地 ISO 时间，再读回确认。

最后简短说明保存路径、回顾更新和待回看变化。若任一步失败，明确已完成和未完成部分，提供可重试或可复制草稿，不报告整体完成。尚未写回的聊天不算已记录。

首页读取已保存文件，自动更新近 7 天日期按钮的打卡状态、累计/本月/近 7 天记录天数，以及折叠的待回看列表。记录天数按日期去重，同一天多篇只计一天；空模板不算打卡。首页不展示正文或 Review 摘要。今天的日期按钮每次新建一篇并开启新对话；当天已保存的各篇通过“查看今天的 N 篇记录”打开。过去已记录日期只有一篇时直接打开，多篇时列出文件供选择。AI 只更新数据，不为刷新视图改 Home 或统计代码。

## 中断与同步

同一篇记录尽量一次由一个设备整理。锁屏/切后台可能中断 Chatting with AI，回前台再继续。首页今天入口始终新建一篇。继续已有记录请打开原对话；原会话已删除或换设备时，明确提供原文件路径，读取后继续，不能仅按日期选一篇追加。跨设备依靠已有的 Obsidian 同步，未同步的结果不能视为已验证完成。
