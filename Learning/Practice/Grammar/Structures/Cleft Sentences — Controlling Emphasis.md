# Cleft Sentences — Controlling Emphasis

> [!info] What it does / when to reach for it
> A cleft splits one idea across two clauses to force the emphasis onto the part I choose. Two main shapes:
> - **It-cleft:** `It's X that…` — spotlights X, great for contrast (`It's X, not Y, that…`).
> - **Wh-cleft:** `What … is X` — builds suspense, lands X at the end (end-weight).
>
> Reach for it when a plain sentence buries the one thing I actually want heard — especially **in speech**, where I can't bold a word, so word order does the highlighting.

> [!example] My sentence — before → after
> **Before (flat, emphasis unclear):** I'm worried about the migration timeline, not the application logic.
> *(Both halves carry equal weight; the contrast is weak.)*
>
> **After (it-cleft):** **It's the migration timeline that worries me — not the application logic.**
> *(Spotlight hard on "migration timeline"; the contrast snaps into focus.)*
>
> **After (wh-cleft):** **What worries me isn't the application logic — it's the migration timeline.**
> *(Holds the real concern back to the end, so it lands last and loudest.)*

> [!tip] What the structure bought me
> Control over the listener's attention in real time. In a stakeholder session this is the difference between a point that registers and one that washes past. I decide what the sentence is *about*.

**Variations worth trying**
- `The thing that concerns me is…` — softer, more conversational than `It's…`
- `All I'm asking for is…` — narrows and downplays the request
- `It was only after the discovery phase that we realised…` — clefts a *time*, foregrounds when the shift happened
- `What we actually need isn't more tooling — it's alignment on scope.` — contrast cleft for redirecting a discussion

> [!warning] Common trap for me
> Overusing it — every sentence as a cleft reads theatrical. Save it for the one point per paragraph that genuinely needs the spotlight.
